商用交付 · 四端

资讯类 App · 四端交付案例

客户端原生渲染 · 服务端 · 管理后台 · H5 分享落地页

项目说明

一次完整的商用交付：端到端的资讯阅读产品，覆盖手机客户端（Android 与 iOS）、 Java 服务端、Vue 3 管理后台，以及供站外打开阅读的 H5 分享落地页。 四端由我一个人从需求梳理、技术选型做到部署上线。

按委托方要求，这里只说明技术方案与实现要点，不展示界面截图、录屏与任何运营数据； 产品名称、品牌标识、域名等均属于委托方，不在公开页面出现。

  • uni-app X（UTS）
  • 蒸汽模式原生渲染
  • Spring Boot
  • MyBatis-Plus
  • MySQL
  • Vue 3 + Element Plus
  • wangEditor
  • Nginx
  • systemd

交付范围

端内容
客户端
Android / iOS		 首页聚合与栏目筛选、全站搜索、文章详情富文本渲染、本机浏览记录与收藏、深浅色主题切换、分享海报生成、手机号验证码登录（未登录可浏览全部内容）
H5 分享落地页 文章详情网页，零外部资源，底部带下载引导，供站外打开或扫码阅读
服务端 数据库设计与部署、内容数据接口、图片存储、分享与 H5 数据接口
管理后台 账号登录、内容发布（富文本 / 配图 / 摘要 / 栏目归属）、定时发布与草稿、内容与栏目管理、数据统计与 Excel 导出

技术要点

  • 原生渲染方案的选择。客户端用 uni-app X 并切到蒸汽模式：视图层由虚拟 DOM 加 diff 改为字节码，逻辑层不再经 UTS 编译成 Kotlin，而由引擎驱动。切换前逐条核对了官方硬约束——只支持组合式 API、CSS 只能简单 class 选择器、scroll-view 的 scroll-y 已废弃、<text> 只能有一个文本节点。实际改动集中在 2 个文件，另加 4 个编译错误的排查。
  • 列表接口不传正文。首屏列表返回的正文长度为 0 字符，只保留配图字段。单页数据量压到最低，弱网下首屏不会被正文拖慢；正文只在进入详情时按需拉取。
  • 富文本的渲染边界。编辑器只保留客户端能渲染的格式：标题、加粗、斜体、下划线、有序与无序列表、引用、分割线、图片、链接、对齐、颜色。表格、多列、视频这类客户端渲不了的，在粘贴时就被拦掉，保证「编辑所见即客户端所见」。
  • 定时发布与草稿。发布方式分立即、定时、存草稿三种。到点由服务端触发发布，不依赖有人打开后台；客户端只消费已发布状态的内容。
  • 本机存储的边界。浏览记录与收藏只存在设备本地，不做云端同步，服务端不保存用户阅读行为明细。这个边界是在需求阶段就定下来的，后续没有为了「功能更完整」而突破它。
  • 分享链路。海报由服务端提供数据、客户端合成，含标题、摘要、配图与二维码；复制链接走 H5 落地页，页面本身零外部资源，站外打开即可阅读。
  • 两套账号体系分开。客户端是手机号加短信验证码，登录态本地保持，未登录可浏览；后台是独立的账号密码体系，密码用 BCrypt 哈希不存明文，连续多次错误锁定一段时间，登录有有效期。
  • 统计口径要写清楚。阅读量存在两种口径：页面上的总量包含已删除内容，导出表格则按未删除过滤。内容盘点不该算已删的，但运营拿导出行数去对总数会对不上，所以两处都在界面上标明了口径，而不是让它成为一个「对不上的数」。
