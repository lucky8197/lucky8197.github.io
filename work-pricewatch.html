运行中 · 阿里云 ECS 双实例

盯价 PriceWatch · 价格库存监控系统

双站点价格与库存监控 · Python + Flask + SQLite 全栈实现

项目介绍

解决的是一个很实际的问题：海外站点的折扣和补货窗口很短，靠人肉刷新根本盯不住。 系统同时监控两个站点——奥莱站约 224 个商品、正价站约 520 个商品，15 分钟一轮定时采集 （5-30 分钟可在面板调整），发现降价、尺码补货、新商品上架、下架后重新上架四类变动时， 实时推送到飞书群。

配套 Web 面板可直接查看商品列表、价格历史曲线、尺码库存矩阵、事件时间线与每轮流量用时， 手机 / 平板 / 电脑均可访问；两个站点以双实例方式（各自的数据库与配置）部署在阿里云 ECS 上， systemd 托管持续运行。

  • Python 3.11
  • Flask
  • APScheduler
  • SQLite
  • 飞书开放平台
  • Next.js 数据接口
  • systemd

技术要点

  • 抓取负载改造 —— 详情抓取从 HTML 页改为走站点 Next.js 数据接口，单页线上传输从 120 KB 降到 18-20 KB：正价站单轮流量 46.2 MB → 11.6 MB（-75%），抓取耗时 150s → 90s，数据新鲜度从「缓存 Age 中位 19 分钟」变为 Age=0 全实时。这一步把 5 分钟高频档从「配额不可行」变成「约 100 GB/月」。
  • 省流量但不吃缓存 —— 站点 CDN 对商品页有 5 分钟到 1 小时的缓存，走缓存能省流量但拿到的是旧数据，会直接损害补货 / 新品通知的及时性。因此给接口 URL 加 cache-buster 强制回源，节省全部来自接口本身更小，不依赖缓存命中。
  • 采集与解析 —— 基于 sitemap.xml 全量发现商品，仅抓取公开页面；随机延时 + 限流退避 + 失败快速重试，跨境链路不稳定的情况下也能长期跑稳。sitemap 全量拉取按轮降频（每 N 轮一次，其余轮复用缓存），且该项可在面板热改——上新 / 大促日一键调成 1。
  • 事件检测 —— 降价（阈值可调，默认 ≥5%）、尺码补货（缺货 → 有货）、新商品、重新上架四类事件；同一变动 24 小时内只通知一次，多变动合并为一条摘要，防骚扰。
  • 流量与用时统计 —— 每个请求在 fetcher 请求路径上记账（下行 / 上行字节、请求数、304 命中），落库到每轮 runs 记录。面板顶栏实时显示本轮流量、设置页给出按天明细与月估算，并区分「应用层口径」与「代理实际占用估算」——对按流量计费的代理套餐，后者才是账单口径，两者差约 30%。
  • 可靠性设计 —— 站点改版 / 解析异常自动告警；sitemap 商品数量骤降守卫（连续 3 轮才认定真实下架）；数据接口整批 404（站点发版失效）时自动回退 HTML 路径，但回退只认 404，避免站点一抖动就白跑一整轮全量；进程异常退出由 systemd 自动拉起。
  • 飞书通知 —— 群机器人 + 自建应用双通道。摘要为纯文字列表、商品名本身带超链接直达商品页，超出长度自动分条；请求体限制在 20 KB 以内，超限依次去图 / 截断文本，避免被飞书拒收导致丢通知。
  • Web 面板 —— 商品列表、价格历史曲线、尺码库存矩阵（颜色 × 尺码）、事件时间线、手动「立即检查」；带访问口令。轮询间隔、降价阈值、去重窗口、sitemap 刷新频率四项可在面板热改，无需重启。
  • 部署运维 —— systemd 一键安装脚本（装依赖、建专用账号、注册服务、健康检查自动完成），数据 30 天滚动清理，升级保留数据库向后兼容（旧库启动时自动补列，历史缺数据展示为「—」而不是伪造 0）。
