盯价 PriceWatch · 价格库存监控系统

可配置站点的价格与库存监控 · Python + Flask + SQLite 全栈实现

项目介绍

电商的折扣和补货窗口往往很短，靠人定时刷新既不现实也容易错过。 这套系统按固定间隔巡检配置好的目标站点，发现降价、尺码补货、新商品上架、 下架后重新上架这四类变动时，实时推送到飞书群。

目标站点、商品数量和巡检间隔都在配置里，同一套代码可以开多个实例分别监控不同站点。 配套的 Web 面板提供商品列表、价格历史曲线、尺码库存矩阵、事件时间线和每轮流量统计， 手机、平板、电脑都能访问。

  • Python 3.11
  • Flask
  • APScheduler
  • SQLite
  • 飞书开放平台
  • systemd

技术要点

  • 采集负载优化。详情页抓取从整页 HTML 改为读取站点自身的数据接口，单页传输从 120 KB 降到 18-20 KB，单轮流量降约 75%，耗时缩短四成。页面里真正需要的字段只占原始响应的一小部分，剩下都是渲染用的资源引用。
  • 数据新鲜度优先。目标站点的 CDN 对商品页有分钟级到小时级缓存，走缓存能省流量，但拿到的可能是旧数据，而补货和新品通知最看重的恰恰是及时性。因此请求时带上避免命中缓存的参数，宁可多传一点也要拿到当前值。
  • 采集与解析。基于站点公开的 sitemap 枚举商品，只抓无需登录的公开页面，不碰账号态内容。请求之间加随机延时，遇到限流自动退避，失败快速重试一次；跨境链路不稳也能长期跑下去。
  • 事件检测。降价（阈值可调，默认 ≥5%）、尺码补货（缺货到有货）、新商品、重新上架四类事件。同一变动 24 小时内只通知一次，多变动合并成一条摘要，避免刷屏。
  • 流量与用时统计。每个请求在 fetcher 的请求路径上记账，记录下行和上行字节、请求数、304 命中，落到每轮的 runs 记录里。面板顶栏显示本轮流量，设置页给按天明细和月估算；同时区分应用层统计值和链路实际占用，按流量计费的场景下后者才是账单口径，两者差约 30%。
  • 可靠性设计。站点改版或解析异常会自动告警；sitemap 商品数量骤降时有守卫，连续 3 轮才认定真下架；数据接口整批 404（站点发版失效）时回退到 HTML 路径，但回退只认 404，否则站点一抖动就白跑一整轮全量。进程异常退出由 systemd 拉起。
  • 飞书通知。群机器人和自建应用两条通道。摘要是一条纯文字列表，商品名本身带超链接直达商品页，超出长度自动分条。请求体压在 20 KB 以内，超限时先去图再截断文本，免得被飞书拒收丢掉通知。
  • Web 面板。商品列表、价格历史曲线、尺码库存矩阵（颜色 × 尺码）、事件时间线、手动「立即检查」，带访问口令。巡检间隔、降价阈值、去重窗口、sitemap 刷新频率这四项可以在面板直接改，不用重启。
  • 部署运维。systemd 一键安装脚本把装依赖、建专用账号、注册服务、健康检查串起来。数据 30 天滚动清理。升级不用重建数据库，旧库启动时自动补列，历史缺数据在面板上显示为「—」，不填 0。

使用边界

这套系统只做一件事：按固定间隔读取目标站点无需登录即可访问的公开页面，用于价格查询、降价提醒与库存监测。

不访问登录后内容、不绕过访问控制、不用于批量采集转售或恶意压测。采集频率保持在保守区间，请求之间带随机延时，遇到限流主动退避。

使用者需自行确认目标站点的服务条款与 robots.txt 未禁止此类访问；对方明确禁止时应立即停止使用。
